### 1.2 解析パス（2系統）

| パス | 技術 | 特徴 |
|------|------|------|
| **AI解析パス**（推奨） | Gemini API / OpenAI API | 意味的な解析、自然言語説明付き、構文サポートが広い |

## 2. データフロー

### 2.1 Code → Flowchart（読み取り方向）

```
[TypeScript/JavaScript ソースコード]
        │
        ├──── AI解析パス ─────────────────────────────────┐
        │     ↓                                           │
        │     [Gemini API / OpenAI API]                   │
        │     ↓ プロンプト: コード + IRスキーマ             │
        │     [IR (JSON)] ← 意味的なフロー + 説明文         │
        │                                                 │
        └──── 静的解析パス ───────────────────────────────┤
              ↓                                           │
              [TypeScriptParser (ts-morph)]               │
              ↓                                           │
              [AST]                                       │
              ↓                                           │
              [IRTransformer]                             │
              [IR (JSON)]                                 │
                                                         │
        ←────────────────────────────────────────────────┘
        [IR]
        ↓ CacheManager（SHA-256で鮮度管理）
        [flowConverter (webview-ui側)]
        ↓ Dagre レイアウト計算
        [React Flow Data]
        ↓
        [FlowChart UI 表示]
```

### 2.2 Node Edit → Code（書き戻し方向）※Phase 3実装予定

```
[ノード上でラベル・値を編集]
        ↓ postMessage({ type: 'nodeEdited', ... })
[Extension Host]
        ↓
[AI (Gemini/OpenAI)] ← 変更内容 + 元のコード + ASTを渡す
        ↓ コード差分を生成
[ts-morph] ← ASTレベルで整合性を保ちながら適用
        ↓
[ソースファイル更新] → エディタに反映
```

## 3. コアコンポーネント詳細

### 3.1 GeminiAnalyzer（AI解析パス）

**ファイル**: [src/core/ai/GeminiAnalyzer.ts](../src/core/ai/GeminiAnalyzer.ts)

**役割**: ソースコードをGemini APIに渡し、IRを直接生成する。

**プロンプト設計**:

- IRスキーマ（ノードタイプ・エッジ定義）をシステムプロンプトとして提供
- `responseMimeType: 'application/json'` で構造化出力を強制
- ノードID命名規則（`node_0`, `node_1`...）をプロンプト内で規定

**エラーハンドリング**:

| エラー | 対応 |
|--------|------|
| 429 クォータ超過 | `GeminiQuotaError` で詳細メッセージ + モデル切り替えアクション |
| 401/403 認証エラー | APIキー確認を促すメッセージ |
| JSONパース失敗 | Markdownコードブロック除去を試みてから再パース |
| IR形式不正 | `validateIR()` で検出、ユーザーにエラー通知 |

**今後の課題**:

- ノードIDの整合性チェック（branches配列のIDが実在するか検証）
- 分岐ラベルの一貫性チェック（"true"/"false" の統一）
- レスポンスが大きすぎる場合のストリーミング対応

### 3.2 TypeScriptParser（静的解析パス）

**ファイル**: [src/parsers/typescript/TypeScriptParser.ts](../src/parsers/typescript/TypeScriptParser.ts)

**役割**: ts-morphを使ってTypeScript/JavaScriptコードをASTに変換する。

**サポート済み構文**:

- 関数宣言（`function foo() {}`）
- アロー関数（`const foo = () => {}`）
- if/else文
- for/whileループ
- 変数宣言（`const`, `let`, `var`）
- return文

**未対応（今後追加予定）**:

- class定義・メソッド
- try-catch
- switch文
- async/await

### 3.3 IRTransformer

**ファイル**: [src/core/transformer/IRTransformer.ts](../src/core/transformer/IRTransformer.ts)

**役割**: ASTをIR（中間表現）に変換する。静的解析パスの変換器。

**変換ルール**:

| ASTノード | IRノード | 備考 |
|-----------|----------|------|
| FunctionDeclaration | IRStartNode + 本体 + IREndNode | 関数の開始/終了を明示 |
| IfStatement | IRControlFlowNode (type: 'if') | then/elseブランチを分岐 |
| ForStatement | IRControlFlowNode (type: 'for') | ループ継続・終了・バックエッジ |
| WhileStatement | IRControlFlowNode (type: 'while') | 同上 |
| VariableDeclaration | IRProcessNode (type: 'variable') | ラベル: `変数名 = 初期値` |
| ReturnStatement | IRProcessNode (type: 'return') | ラベル: `return 値` |

### 3.4 CacheManager

**ファイル**: [src/core/cache/CacheManager.ts](../src/core/cache/CacheManager.ts)

**役割**: AST/IRキャッシュを統括し、パフォーマンスを最適化する。

**キャッシュ戦略**:

1. ファイルのSHA-256ハッシュで鮮度を確認
2. キャッシュの有効期限（デフォルト1時間）をチェック
3. キャッシュヒット → 即返却、ミス → 新規生成して保存

**キャッシュファイル構造**:

```
.prismcode/
├── cache/
│   ├── ast-cache/   # ts-morphのAST結果
│   └── ir-cache/    # IR変換結果
├── index.json       # ファイルハッシュ管理
└── config.json      # キャッシュ設定
```

**パフォーマンス実績**:

| ファイル規模 | キャッシュなし | キャッシュあり |
|------------|--------------|--------------|
| 100行 | ~50ms | ~5ms |
| 500行 | ~200ms | ~10ms |
| 2000行 | ~1000ms | ~20ms |

### 3.5 FlowChartPanel

**ファイル**: [src/webview/FlowChartPanel.ts](../src/webview/FlowChartPanel.ts)

**役割**: エディタエリアにWebViewパネルを作成し、IRデータを送受信する。

**メッセージング仕様**:

| 方向 | type | データ | 説明 |
|------|------|--------|------|
| Extension → WebView | `updateFlow` | `IR` | フローチャート更新 |
| Extension → WebView | `updateMacroView` | `MacroViewData` | マクロビュー表示 |
| WebView → Extension | `jumpToCode` | `{ location }` | コード行ジャンプ（Phase 2） |
| WebView → Extension | `nodeEdited` | `{ nodeId, newValue }` | ノード編集（Phase 3） |

## 4. WebView UI

### 4.1 コンポーネント構成

```
webview-ui/src/
├── App.tsx                    # メッセージ受信・状態管理
├── components/
│   ├── FlowChart.tsx          # React Flow統合
│   └── nodes/
│       ├── StartNode.tsx      # 開始ノード（緑・丸）
│       ├── EndNode.tsx        # 終了ノード（赤・丸）
│       ├── ProcessNode.tsx    # 処理ノード（青・矩形）
│       ├── IfNode.tsx         # 分岐ノード（オレンジ・菱形）
│       └── LoopNode.tsx       # ループノード（紫・角丸）
├── types/
│   └── ir.ts                  # IR型定義（Extension側と同期）
└── utils/
    └── flowConverter.ts       # IR → React Flow変換 + Dagreレイアウト
```

### 4.2 flowConverter の処理

1. IRノードをReact Flowノード形式に変換（typeマッピング）
2. IRエッジをReact Flowエッジに変換（label保持、`smoothstep`タイプ）
3. Dagreグラフにノード・エッジを登録
4. `dagre.layout()` でTB（Top to Bottom）方向のレイアウト計算
5. 計算済み座標をReact Flowノードに適用

## 7. 開発ワークフロー

```bash
# 依存関係のインストール
pnpm install
cd webview-ui && pnpm install && cd ..

# 開発（監視モード）
pnpm run watch                  # Extension側

# WebView UIビルド
pnpm run compile:webview

# デバッグ実行
F5                              # Extension Development Hostが起動

# 本番ビルド
pnpm run vscode:prepublish
```

### よくある問題

| 問題 | 原因 | 解決 |
|------|------|------|
| フローチャートが表示されない | WebView UIがビルドされていない | `pnpm run compile:webview` |
| Gemini APIエラー | APIキー未設定 or クォータ超過 | 設定でキー確認、モデル切り替え |
| キャッシュが古い | ファイル変更が検知されていない | `prismcode.clearCache` コマンド実行 |
| パース失敗 | 未対応構文が含まれる | Gemini解析パスに切り替え |
