# Prism Code 企画書：AI-first 双方向コード可視化プラットフォーム

---

## 1. 概要

Prism Codeは、ソースコードをそのままAIに渡して意味的に解析・可視化し、
**「コードとビジュアルの双方向編集」「ライブデバッグ可視化」「AI補完」**を
VSCode内でシームレスに実現する拡張機能です。

「コードを書く」作業から「デザインして構築する」作業へ——
ビジュアルとコードの境界を溶かし、開発の透明性を究極まで高めます。

---

## 2. 背景・課題

### 先行事例

| ツール | 特徴 | 限界 |
| :--- | :--- | :--- |
| Code2Flow / Mermaid | テキストからフロー図生成 | IDEに統合されていない、手動記述が必要 |
| Flowgorithm | 初心者向けフロー図エディタ | 実プロジェクトのコードに使えない |
| GitHub Copilot / Cursor | コード補完・生成 | 視覚的な理解支援はない |
| AST Explorer | 構文木の確認 | 初学者には抽象度が高すぎる |
| Eraser / Whimsical | ドキュメント＋ダイアグラム統合 | 「既存コードをIDE内でリアルタイム可視化」機能はない |
| Rete.js | ノードベースのビジュアルプログラミング | コードとの双方向編集は未対応 |
| React Flow | インタラクティブなグラフ描画 | コード解析・双方向編集は自前で実装が必要 |
| Node-RED | フローエディタ＋実行環境 | 主にIoT向け、一般的なコードベースには不向き |

### 本質的な課題

- UIの変更がコードのどこに影響するか分かりにくい
- ロジック（フロー）と見た目の記述が分離しており全体像の把握に時間がかかる
- 既存ツールはどれも「一方通行」（コード→図、または図→コードのどちらか）
- デバッグ時に「今どこを実行しているか」を視覚的に追う手段がない

## 3. 提案するソリューション

### 3.1 AI-first コード解析

ソースコードをそのままAI（Gemini / OpenAI / ローカルAI）に渡し、
構文ではなく**意味**を理解したフロー構造・説明を生成します。

#### AI解析の流れ

```text
[ソースコード]
    ↓ AI（Gemini API / OpenAI API）に直接渡す
[意味的なフロー解析 + 各ノードの自然言語説明]
    ↓
[React Flow + Dagre でインタラクティブ表示]
```

ts-morphによるAST解析はオフライン・フォールバックとして共存。

#### 双方向（Bi-directional）同期

**Code → Node（既存機能）**

- 右クリック or コマンドで現在のコード・選択範囲を即座にノードグラフ化
- ノードをクリックすれば元のコード行にジャンプ

**Node → Code（新機能）**

- ノード上のラベル・値を編集すると、背後の `.ts`/`.js` ファイルをAIが書き換え
- 文字列操作ではなくASTレベルで整合性を保った変換
- フローチャートのエッジ接続変更 → 対応するif文・ループ構造をリファクタリング

### 3.3 実行状態の「ライブ・デバッグ」可視化

VSCode Debug Adapter Protocolと連携し、**「今動いているデータ」**を可視化します。

- **ブレークポイントの可視化**: デバッグ実行中、現在停止中のノードを光らせる
- **データの流速表示**: 処理が重い関数の接続線を太く・赤く表示してボトルネックを特定
- **Time Travel Debugging**: スライダーで過去の変数状態をノードラベルに再現

### 3.4 AIによる自動レイアウト・補完

- **自然言語からのノード生成**: サイドバーのチャット欄に指示するだけでフローを自動構築
- **ノードの「推奨接続」**: 次に繋ぐべきノードをAIがリコメンド（例：エラーハンドリング）
- **リファクタリング支援**: 「この複雑なノード群を1つのカスタムノードにまとめて」をワンクリックで実行

### 3.5 AIによるビジュアル自動選択（マルチテンプレート）

コードの内容に応じてAIが最適な図の種類を自動判断し、6種類のテンプレートから選択します。

| テンプレート | 用途 | AI選択トリガーの例 |
| :--- | :--- | :--- |
| `flowchart` | 制御フロー（デフォルト） | `if` / `for` / `while` が多い通常の関数 |
| `class-diagram` | クラス・インターフェース構造 | `class`, `interface`, `extends`, `implements` |
| `screen-transition` | 画面遷移 | `<Route>`, `navigate()`, `useRouter` |
| `sequence-diagram` | 関数呼び出し順序 | `async/await` チェーン・API コール |
| `state-machine` | 状態遷移 | `useState`, `useReducer`, `XState` |
| `dependency-graph` | モジュール依存関係 | `import/export` が主体のファイル |

ユーザーはUIのテンプレートバーから手動で切り替えることも可能。

### 3.6 プロジェクト特化型プリセット

- **React Hooks Visualizer**: `useEffect`の依存配列・`useState`の変化を専門追跡
- **XState / State Machine連携**: 状態遷移図をGUIで作りながら厳密なステートマシンコードを同期生成

## 4. 機能フェーズ

### Phase 1（完了）：コア可視化パイプライン

- ✅ TypeScript/JavaScript の解析（ts-morph + Gemini API）
- ✅ 言語非依存IR（中間表現）への変換
- ✅ React Flow + Dagre による自動レイアウト付きフローチャート描画
- ✅ プロジェクト全体のファイル・関数インデックス（マクロビュー初期版）
- ✅ SHA-256ハッシュ＋有効期限によるキャッシュ機構
- ✅ Gemini API / OpenAI API による解析経路の試作

### Phase 2（進行中）：インタラクティブ性の強化

- ノードクリックでソースコード行へジャンプ
- コード編集時の自動更新（ファイルウォッチャー統合）
- 構文サポート拡張（class・try-catch・switch・async/await）
- AI説明機能の安定化（ノードごとの自然言語解説）

### Phase 3（次期）：双方向編集 + ライブデバッグ

- Node → Code 変換（AIによるコード書き換え）
- VSCode Debug Adapter Protocol 連携（ライブデバッグ可視化）
- Time Travel Debugging（変数状態の再現）

### Phase 4（将来）：AI補完 + プリセット

- 自然言語からのノード自動生成
- マルチテンプレート専用レンダラーの完成（class-diagram / screen-transition / sequence-diagram / state-machine）
- React Hooks Visualizer
- XState / State Machine連携
- 多言語対応（Java・Python）

---

## 7. 独自性・差別化

1. **IDE内で即時可視化**: Webサービス不要、使い慣れたVSCodeの中で動く
2. **双方向同期**: コード↔ビジュアルの真の双方向編集（業界初クラス）
3. **ライブデバッグ可視化**: 実行中の状態をリアルタイムでノードに反映
4. **AI-first解析**: 構文だけでなく「意図」を理解したフロー＋自然言語説明
5. **言語非依存IR設計**: 新言語追加時にパーサーを差し替えるだけで対応可能
6. **AIによるビジュアル自動選択**: コードの内容を解析し、フローチャート・クラス図・画面遷移図・シーケンス図・状態遷移図・依存関係グラフの中から最適な表現を自動選択
